## List jobs

```
GET /queue/jobs
```

**Auth:** API Key required

### Query parameters

<ParamField query="limit" type="number" default="50">
  Maximum number of jobs to return (pagination).
</ParamField>

<ParamField query="offset" type="number" default="0">
  Number of jobs to skip (pagination offset).

  <Warning>
    `offset` is ignored whenever `status` is set. The filtered path calls
    `getJobsByStatus(status, limit)`, which takes no offset, so paginating a
    filtered list re-returns the same first page. `offset` is echoed back in the
    response either way.
  </Warning>
</ParamField>

<ParamField query="status" type="string">
  Filter by job status. One of: `pending`, `processing`, `completed`, `error`, `cancelled`.
</ParamField>

### Response

This endpoint serves database rows as they are stored. Field names are `snake_case`, not `camelCase`, and timestamps are epoch milliseconds, not ISO 8601 strings.

```json
{
  "jobs": [
    {
      "id": "job_abc123",
      "file_path": "videos/clip.mp4",
      "params_json": "{\"width\":640}",
      "cache_path": "cache/w_640/videos/clip.mp4",
      "status": "completed",
      "priority": 2,
      "progress": 100,
      "error": null,
      "retry_count": 0,
      "max_retries": 3,
      "created_at": 1773567000000,
      "started_at": 1773568200000,
      "completed_at": 1773568305000
    }
  ],
  "limit": 50,
  "offset": 0,
  "count": 1
}
```

<ResponseField name="jobs" type="array">
  <Expandable title="Job object">
    <ResponseField name="id" type="string">Unique job identifier.</ResponseField>
    <ResponseField name="file_path" type="string">Storage path of the video being processed.</ResponseField>
    <ResponseField name="params_json" type="string">The transformation parameters the job was queued with, as a JSON string. Together with `file_path` this is the key a job is looked up by.</ResponseField>
    <ResponseField name="cache_path" type="string">Where the finished variant is written.</ResponseField>
    <ResponseField name="status" type="string">`pending` · `processing` · `completed` · `error` · `cancelled`</ResponseField>
    <ResponseField name="priority" type="number">Processing priority, lower runs first. Thumbnails are queued at `1` and transformations at `2`.</ResponseField>
    <ResponseField name="progress" type="number">Progress percentage, 0 to 100.</ResponseField>
    <ResponseField name="error" type="string">Error message when `status` is `error`, `null` otherwise.</ResponseField>
    <ResponseField name="retry_count" type="number">Attempts made so far.</ResponseField>
    <ResponseField name="max_retries" type="number">Attempt ceiling, from `VIDEO_JOB_RETRY_MAX`.</ResponseField>
    <ResponseField name="created_at" type="number">Epoch milliseconds when the job was queued.</ResponseField>
    <ResponseField name="started_at" type="number">Epoch milliseconds when processing started, `null` while pending.</ResponseField>
    <ResponseField name="completed_at" type="number">Epoch milliseconds when processing finished, `null` until then.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="count" type="number">Number of jobs in this response, not the total matching the filter.</ResponseField>

<Note>
  [Video Status](/api-reference/video/status) returns the same jobs in a
  converted shape: `camelCase` keys and ISO 8601 timestamps. The two endpoints
  do not agree on field names by design, one serves rows and the other serves a
  view model.
</Note>

### Example

```bash
# List all failed jobs
curl "http://localhost:3000/queue/jobs?status=error&limit=20" \
  -H "Authorization: Bearer <api_key>"
```

## Retry job

```
POST /queue/jobs/{jobId}/retry
```

Re-queues a failed job for processing.

**Auth:** API Key required

### Path parameters

<ParamField path="jobId" type="string" required>
  ID of the job to retry. Must have `error` status.
</ParamField>

### Response

```json
{
  "success": true,
  "message": "Job scheduled for retry"
}
```

**Status codes:** `200` success · `400` job not in error state · `500` error

### Example

```bash
curl -X POST http://localhost:3000/queue/jobs/job_abc123/retry \
  -H "Authorization: Bearer <api_key>"
```

## Cancel job

```
POST /queue/jobs/{jobId}/cancel
```

Cancels a pending job before it starts processing.

**Auth:** API Key required

### Path parameters

<ParamField path="jobId" type="string" required>
  ID of the job to cancel. Must have `pending` status.
</ParamField>

### Response

```json
{
  "success": true,
  "message": "Job cancelled"
}
```

**Status codes:** `200` success · `400` job not pending · `500` error

### Example

```bash
curl -X POST http://localhost:3000/queue/jobs/job_abc123/cancel \
  -H "Authorization: Bearer <api_key>"
```

## Delete job

```
DELETE /queue/jobs/{jobId}
```

Permanently removes a job record from the queue.

**Auth:** API Key required

### Path parameters

<ParamField path="jobId" type="string" required>
  ID of the job to delete.
</ParamField>

### Response

```json
{
  "success": true,
  "message": "Job deleted"
}
```

**Status codes:** `200` success · `400` failed · `500` error

### Example

```bash
curl -X DELETE http://localhost:3000/queue/jobs/job_abc123 \
  -H "Authorization: Bearer <api_key>"
```
