---
title: "Health"
description: "Check server and database availability"
---

**Self-hosted only.** Not available on Cloud.

Two probes. `GET /health` is a public liveness check, `GET /health/database` needs an API key and reports the PostgreSQL connection.

```bash
curl https://media.example.com/health
```

## Server health

```
GET /health
```

**Auth:** Public (rate limited)

Quick liveness check, use this for load balancer health probes or uptime monitoring.

```json
{
  "status": "ok",
  "timestamp": "2024-03-15T10:30:00.000Z",
  "service": "openinary-api"
}
```

**Status codes:** `200` healthy

## Database health

```
GET /health/database
```

```bash
curl https://media.example.com/health/database \
  -H "Authorization: Bearer <api_key>"
```

**Auth:** API Key required

Detailed diagnostic, checks the PostgreSQL connection and reports its latency.

```json
{
  "status": "ok",
  "timestamp": "2024-03-15T10:30:00.000Z",
  "database": {
    "connected": true,
    "latencyMs": 2
  }
}
```

| Field                        | Type      | Description                                                                             |
| ---------------------------- | --------- | ----------------------------------------------------------------------------------------- |
| `database.connected`         | `boolean` | Whether the database connection is active                                               |
| `database.latencyMs`         | `number`  | Round-trip time of the connectivity probe, in milliseconds                              |

**Status codes:** `200` healthy · `503` database connection failed
