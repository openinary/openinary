---
title: "Copy File"
description: "Duplicate a file inside its own folder"
---

## Endpoint

```
POST /storage/{path}/copy
```

**Auth:** API key required. A dashboard session cookie also works.

<Note>
  A copy always lands in the source file's own folder. This endpoint takes no
  request body, and there is no way to copy into a different folder in one call.
  To place a duplicate elsewhere, copy it and then
  [move](/api-reference/storage/move) it.
</Note>

<Note>
  Only files can be copied. A folder path returns `404`. To copy a folder, copy
  its files one by one.
</Note>

## Path parameters

<ParamField path="path" type="string" required>
  Path to the file relative to the storage root. Use the `path` of a file
  returned by [List Storage](/api-reference/storage/list).

`photo.jpg` · `photos/portrait.jpg`

</ParamField>

## Response

```json
{
  "success": true,
  "path": "photos/portrait copy.jpg"
}
```

<ResponseField name="success" type="boolean">
  `true` if the copy succeeded.
</ResponseField>

<ResponseField name="path" type="string">
  Path of the new copy. The name is the source name with ` copy` appended before
  the extension. If that name is taken, a counter is added: `portrait copy.jpg`,
  then `portrait copy (1).jpg`, `portrait copy (2).jpg`, and so on.
</ResponseField>

**Status codes:**

| Code  | Meaning                                        |
| ----- | ---------------------------------------------- |
| `200` | Copy created                                   |
| `400` | Path is missing                                |
| `404` | File not found, or the path is a folder        |
| `500` | Storage backend failed to copy                 |

## Example

```bash
curl -X POST http://localhost:3000/storage/photos/portrait.jpg/copy \
  -H "Authorization: Bearer <api_key>"
```

```json
{ "success": true, "path": "photos/portrait copy.jpg" }
```
