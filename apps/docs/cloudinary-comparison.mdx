---
title: "Cloudinary vs Openinary"
description: "An honest, feature-by-feature comparison of what Cloudinary offers versus what Openinary supports today."
---

Openinary covers core transformation and delivery well: resize, crop, format conversion, quality, video trimming, upload, caching and signed URLs. It does not cover image effects, AI and generative features, adaptive streaming, overlays, or an enterprise DAM layer.

Cloudinary is a mature commercial product with years of development behind it. Openinary is early-stage open source, built for teams that want to self-host. This page is the honest version of that gap.

**Openinary fits when** you want control over your infrastructure and data, your use case is core image and video delivery, you are comfortable running Docker somewhere, and you would rather not pay per transformation.

**Cloudinary is the better choice today when** you need AI or generative transformations, adaptive streaming, image effects and overlays, a managed CDN with no infrastructure of your own, team roles or SSO, a full DAM with search and workflows, official SDKs in your language, or webhooks.

The tables below are the detail behind that summary.

---

## Image transformations

| Feature                      | Cloudinary                                                      | Openinary                                           |
| ---------------------------- | --------------------------------------------------------------- | --------------------------------------------------- |
| Resize (`w`, `h`)            | ✓                                                               | ✓                                                   |
| Aspect ratio (`ar`)          | ✓                                                               | ✓                                                   |
| Crop modes                   | ✓ 14 modes (`fill`, `pad`, `thumb`, `lfill`, `imagga_crop`, …)  | ✓ 5 modes (`fill`, `fit`, `scale`, `crop`, `pad`)   |
| Gravity / focal point        | ✓ Face, body, object, custom coordinates, auto (entropy)        | ✓ Face, compass directions, auto (entropy), center  |
| Rotation (`a`)               | ✓ Degrees + `vflip`, `hflip`, `auto_right`, `auto_left`, EXIF   | ✓ Degrees + EXIF `auto`                             |
| Background color (`b`)       | ✓ Colors, blurred, `gen_fill` (AI-generated)                    | ✓ Hex, `rgb:`, `transparent`, `white`, `black`      |
| Round corners (`r`)          | ✓                                                               | ✓ Uniform, per-corner, or `max` (circle/oval)       |
| Quality (`q`)                | ✓ Numeric + `auto` (content-aware)                              | ✓ Numeric 1-100 + `auto` (per-format)               |
| Format (`f`)                 | ✓ AVIF, WebP, JPEG, PNG, GIF, HEIC, SVG, TIFF, BMP, PDF, `auto` | ✓ AVIF, WebP, JPEG, PNG, GIF, `auto` (via Accept header) |
| Auto format selection        | ✓                                                               | ✓                                                   |
| Device pixel ratio (`dpr`)   | ✓ Including `auto`                                              | ✗                                                   |
| Zoom (`z`)                   | ✓                                                               | ✗                                                   |
| Named transformations        | ✓ (reusable presets)                                            | ✗                                                   |
| Chained transformations      | ✓ (multiple steps in one URL)                                   | ✗                                                   |
| Default image fallback (`d`) | ✓                                                               | ✗                                                   |
